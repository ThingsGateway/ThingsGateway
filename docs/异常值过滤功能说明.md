# 变量异常值过滤功能说明

## 1. 功能概述

为 `Variable`（设备变量）新增 **异常值过滤（Outlier Filter）** 能力。当采集到的变量值发生变化时，系统会自动对新值进行异常检测，拦截不合理的数据，防止异常数据进入业务流程。

### 设计原则

- **仅在线时生效**：设备离线时不执行过滤，避免干扰离线状态处理。
- **仅在值变化时检查**：值未发生变化时不会触发过滤逻辑，减少不必要的计算开销。
- **多级过滤、顺序执行**：三种过滤模式按顺序依次检查，任一模式判定异常即标记为异常值。
- **连续异常容错**：当异常值连续出现达到设定次数时，认定数据确实发生了变化，自动接受该值。

---

## 2. 三种过滤模式详解

### 2.1 合理范围过滤

检查新值是否在预设的合理范围 `[最小值, 最大值]` 内。超出范围的值被视为异常。

**典型场景**：温度传感器量程为 -40°C ~ 120°C，超出此范围的值显然是采集异常。

#### 配置属性

| 属性名 | 数据库列 | 类型 | 默认值 | 说明 |
|---|---|---|---|---|
| `RangeFilterEnable` | `合理范围过滤使能` | `bool` | `false` | 是否启用合理范围过滤 |
| `RangeFilterMinValue` | `最小值` | `decimal` | `0` | 允许的最小值（含） |
| `RangeFilterMaxValue` | `最大值` | `decimal` | `100` | 允许的最大值（含） |

#### 判定逻辑

```
如果 新值 < 最小值 或 新值 > 最大值：
    → 标记为异常
```

---

### 2.2 变化幅度过滤

检查新值与上次值之间的变化幅度是否超过允许上限。支持 **绝对值** 和 **百分比** 两种判定方式，两者同时生效。

**典型场景**：压力变送器正常波动范围为 ±5 单位 或 ±10%，突然跳变 100 单位显然是采集异常。

#### 配置属性

| 属性名 | 数据库列 | 类型 | 默认值 | 说明 |
|---|---|---|---|---|
| `AmplitudeFilterEnable` | `变化幅度过滤使能` | `bool` | `false` | 是否启用变化幅度过滤 |
| `MaxAmplitude` | `最大变化幅度` | `decimal` | `100` | 允许的最大绝对变化量（**> 0 时生效**，设为 0 则跳过绝对值检查） |
| `MaxAmplitudePercent` | `最大变化幅度%` | `decimal` | `100` | 允许的最大变化百分比（单位：%）（**> 0 时生效**，设为 0 则跳过百分比检查） |

#### 判定逻辑

```
绝对变化量 = |新值 - 旧值|

步骤1 — 绝对值检查（仅 MaxAmplitude > 0 时执行）：
    如果 绝对变化量 > MaxAmplitude：
        → 标记为异常

步骤2 — 百分比检查（仅 MaxAmplitudePercent > 0 且 步骤1未触发 且 旧值≠0 时执行）：
    变化百分比 = 绝对变化量 / |旧值| × 100
    如果 变化百分比 > MaxAmplitudePercent：
        → 标记为异常
```

> **注意**：
> - 当 `MaxAmplitude` 设为 `0` 时，跳过绝对值检查，仅执行百分比检查。
> - 当 `MaxAmplitudePercent` 设为 `0` 时，跳过百分比检查，仅执行绝对值检查。
> - 两者同时设为 `0` 时，即使 `AmplitudeFilterEnable` 为 `true`，幅度过滤也不会触发任何拦截。
> - 当旧值为 `0` 时，跳过百分比检查（避免除零错误）。

#### 两种方式的区别

| 对比维度 | 绝对值过滤 (`MaxAmplitude`) | 百分比过滤 (`MaxAmplitudePercent`) |
|---|---|---|
| 适用场景 | 变量值数量级固定 | 变量值数量级差异大 |
| 示例 | 温度波动不超过 ±5°C | 流量变化不超过 ±20% |
| 优势 | 简单直观 | 自适应不同数量级 |

---

### 2.3 连续异常过滤

当异常值 **连续出现** 达到设定次数后，系统认定数据确实发生了合理变化（如设备参数被人工调整），自动接受该值并清零计数器。

**典型场景**：温度设定值从 50°C 调整到 200°C，首次变化幅度超限被拦截，但如果连续 3 次都是 200°C，则说明确实发生了变化，应当接受。

#### 配置属性

| 属性名 | 数据库列 | 类型 | 默认值 | 说明 |
|---|---|---|---|---|
| `ContinuousFilterEnable` | `连续异常过滤使能` | `bool` | `false` | 是否启用连续异常过滤 |
| `MaxContinuousCount` | `连续异常最大次数` | `int` | `3` | 连续异常值达到此次数后接受该值 |

#### 判定逻辑

```
当值被判定为异常时：
    如果 连续异常过滤已启用：
        连续异常计数器++
        如果 计数器 >= MaxContinuousCount：
            → 计数器清零，接受该值（返回 true）
        否则：
            → 拒绝该值（返回 false）
    否则：
        → 直接拒绝该值（返回 false）

当值正常（未被判定为异常）时：
    → 计数器清零
```

> **重要**：连续异常计数器仅在值实际变化（`changed == true`）时才递增，重复采集到相同的值不会增加计数。

## 3. 整体执行流程

```
┌─────────────────────────────────────────────────────┐
│                   Set() 方法                         │
│                                                      │
│  1. 计算值是否变化 (changed)                          │
│  2. 检查条件: (changed || setChanged) && _isOnline    │
│     ├─ 条件不满足 → 跳过过滤，直接赋值                  │
│     └─ 条件满足 → 调用 ApplyOutlierFilter(data)       │
│                                                      │
├─────────────────────────────────────────────────────┤
│              ApplyOutlierFilter(data)                │
│                                                      │
│  1. 前置检查                                          │
│     ├─ 无任何过滤启用 → 直接通过                       │
│     └─ 数据无法转为数值 → 直接通过（不过滤非数值类型）    │
│                                                      │
│  2. 合理范围过滤                                      │
│     └─ 新值不在 [Min, Max] → 标记异常                  │
│                                                      │
│  3. 绝对幅度过滤（MaxAmplitude > 0 时）                 │
│     └─ |新值 - 旧值| > MaxAmplitude → 标记异常         │
│                                                      │
│  4. 百分比幅度过滤（MaxAmplitudePercent > 0 且旧值≠0）   │
│     └─ 变化% > MaxAmplitudePercent → 标记异常          │
│                                                      │
│  5. 异常结果处理                                      │
│     ├─ 未异常 → 计数器清零，返回 true（接受）           │
│     └─ 已异常                                        │
│          ├─ 连续过滤启用                               │
│          │   ├─ 计数 >= 上限 → 清零，返回 true（接受）  │
│          │   └─ 计数 < 上限 → 返回 false（拒绝）       │
│          └─ 连续过滤未启用 → 返回 false（拒绝）         │
│                                                      │
├─────────────────────────────────────────────────────┤
│                  返回到 Set()                         │
│                                                      │
│  ├─ ApplyOutlierFilter 返回 true → 正常赋值流程       │
│  └─ ApplyOutlierFilter 返回 false                    │
│       → 触发 VariableCollectChange（更新采集时间）      │
│       → Set() 返回 false                             │
│       → SetValue() 返回错误信息                       │
│       → 变量值不更新，保持上一次的有效值                 │
└─────────────────────────────────────────────────────┘
```

## 7. 日志输出

过滤过程中的关键事件会通过 `LogMessage` 输出日志：

| 日志级别 | 事件 | 示例 |
|---|---|---|
| `Trace` | 范围过滤触发 | `变量A Outlier filter: value 250 out of range [0, 200]` |
| `Trace` | 绝对幅度过滤触发 | `变量A Outlier filter: amplitude 150 exceeds max 100` |
| `Trace` | 百分比幅度过滤触发 | `变量A Outlier filter: amplitude 85.50% exceeds max 50%` |
| `Information` | 连续异常达上限，接受值 | `变量A Outlier filter: continuous anomaly count reached 3, accepting value 250` |
| `Warning` | 值被拒绝（由 `SetValue` 输出） | `变量A Outlier filter rejected value` |

## 8. 注意事项

1. **非数值类型不过滤**：如果变量值无法转换为 `decimal`（如字符串、布尔值），则跳过所有过滤，直接接受该值。
2. **首次赋值不过滤幅度**：变量的 `Value` 为 `null` 时（首次采集），幅度过滤不会执行（无旧值可比较），但范围过滤仍然生效。
3. **设备离线时清零计数器**：设备离线时，`SetValue` 会清零连续异常计数器，确保重新上线后不会携带历史状态。
4. **三种过滤独立启用**：每种过滤模式可独立开启或关闭，互不影响。
5. **默认全部关闭**：所有过滤使能默认为 `false`，不影响现有变量的行为。
6. **幅度阈值为 0 时跳过**：`MaxAmplitude` 或 `MaxAmplitudePercent` 设为 `0` 时，对应的检查项将被跳过，不会触发拦截。可以利用此特性只启用其中一种幅度检查方式。
